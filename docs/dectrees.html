Decision Trees

Decision Trees Overview

Decision Trees represent a powerful class of supervised non-parametric machine learning models used for both classification and regression tasks by recursively partitioning a dataset into increasingly homogeneous, or pure, subsets based on feature thresholds. Unlike probabilistic models such as Naive Bayes, a Decision Tree creates an explicit structure where internal nodes represent tests on specific independent attributes, branches denote the outcomes of those tests, and terminal leaf nodes deliver the final predicted class label. Within machine learning pipelines, this algorithmic approach provides a major structural advantage: it generates a highly transparent, readable sequence of logical checkpoints, as shown in Figure 1B below. This allows stakeholders to easily interpret exactly why a model predicts a specific outcome.

To unify the supervised learning analysis, the Decision Tree models will be evaluated across the exact same four predictive modeling tasks established in the Naive Bayes section. Holding feature sets and labeled target vectors uniform establishes a rigorous comparative framework to analyze how an iterative, non-parametric spatial-splitting model stacks up against a probabilistic, feature-independent baseline.

The Mathematics of Node Splits: Gini, Entropy, and Information Gain

To construct an optimal tree, the algorithm must determine the exact feature and spatial boundary line to split the data at any given node. This is achieved by evaluating mathematical metrics that quantify the statistical chaos, or impurity, of the target labels within that node. The tree greedily selects the split that minimizes downstream impurity, thereby maximizing the purity of the child nodes.

1. Gini Impurity

Gini Impurity measures the probability of a random element from a node being incorrectly labeled if it were randomly classified according to the label distribution in that subset. It spans a continuous range from 0.0 (a pure node, containing only one class) to 0.5 (a balanced node, perfectly split between two classes). The formula for Gini Impurity at node t is expressed as:

$$Gini(t) = 1 - \sum_{i=1}^{c} (p_i)^2$$

Where \( p_i \) represents the proportion of samples belonging to class i at t.

2. Entropy

Entropy measures the total level of class randomness at a specific node. Like Gini Impurity, a perfectly pure node containing only one class receives an Entropy score of 0.0. However, the maximum Entropy score, representing a node evenly split between two classes, is 1.0. The formula for Entropy at node t is expressed as:

$$Entropy(t) = -\sum_{i=1}^{c} p_i \log_2(p_i)$$

3. Information Gain

Information Gain is the operational metric that determines which split is executed. It calculates the net reduction in statistical impurity achieved by partitioning a parent node into smaller child branches. The model tests every possible split threshold across all features and selects the single boundary line that yields the maximum Information Gain. The mathematical formula is defined as:

$$Gain(A) = \text{Impurity}(\text{Parent}) - \sum_{v \in \text{Children}} \frac{|N_{\text{child}}|}{|N_{\text{parent}}|} \times \text{Impurity}(\text{Child})$$

Step-by-Step Splitting Example (Entropy)

To demonstrate how these metrics function under real-world conditions, consider a parent node containing 100 challenged pitches: 60 are labeled as Overturned (1) and 40 labeled as Confirmed (0).

Step 1: Calculate Parent Node Entropy

Before any split is executed, the baseline uncertainty of the parent node is computed using the class proportions (p1 = 0.60 and p0 = 0.40):

$$Entropy(Parent) = -(0.60 \log_2(0.60) + 0.40 \log_2(0.40)) = 0.971$$

Step 2: Evaluate a Candidate Feature Split

Suppose the model tests a split on the current inning: inning <= 5. This split divides the 100 pitches into two child nodes:

  • Left Child Node (Condition True): 50 pitches (45 Overturned, 5 Confirmed)
  • Right Child Node (Condition False): 50 pitches (15 Overturned, 35 Confirmed)

Step 3: Compute Child Node Impurities

$$Entropy(Left Child) = -(0.9 \log_2(0.9) + 0.1 \log_2(0.1)) = 0.469$$
$$Entropy(Right Child) = -(0.3 \log_2(0.3) + 0.7 \log_2(0.7)) = 0.881$$

Step 4: Compute Final Information Gain

$$Weighted Child Entropy = (0.5 \times 0.469) + (0.5 \times 0.881) = 0.675$$
$$Information Gain = Parent Entropy - Weighted Child Entropy = 0.971 - 0.675 = 0.296$$

Because this spatial boundary line successfully reduces the Entropy by an Information Gain score of 0.296, the algorithm marks this checkpoint as a highly viable candidate node split.

The Infinite Tree Phenomenon

It is generally possible to generate an infinite number of unique decision trees from a continuous dataset. Because continuous attributes (such as pitch location coordinates) are composed of floating-point numbers measured out to multiple decimal places, there is a mathematically infinite number of potential splitting thresholds between any two numerical values. Furthermore, a data scientist can alter the tree by tweaking structural hyperparameters:

  • Altering the maximum allowed splitting layer depth (max_depth).
  • Adjusting the minimum sample allocation required to form a terminal node (min_samples_leaf).
  • Modifying the required split threshold criteria (min_impurity_decrease).
  • Switching the absolute baseline impurity function between Gini Impurity and Entropy.

By shifting these parameters even minutely, the algorithm will generate an infinite variety of distinct structural tree geometries from the exact same underlying dataset.

Data Prep

Supervised machine learning with Decision Trees requires a fully labeled historical dataset to calculate the mathematical impurity reductions that guide feature splits. In alignment with the Naive Bayes models, the Decision Trees pipeline is built around the exact same four predictive target variables, split across two distinct categories of labeled outcomes:

  • Challenge Intent (“Will pitch get challenged?”) Targets: Labeled as "Challenged" (1) or "Not Challenged" (0).
  • Challenge Outcome (“Will challenge get overturned?”) Targets: Labeled as "Overturned" (1) or "Confirmed" (0).

To enforce strict validation integrity and prevent data leakage, the feature matrices and label vectors are programmatically partitioned into a Training Set (80%) and a Testing Set (20%) using a stratified random split. Stratification is a critical step because it ensures that both the training and testing sets mirror the exact proportion of target labels found in the dataset, preventing the model from experiencing class starvation during validation.

Proactive Imbalance Correction via Class Weighting

The exploratory data analysis phase revealed an extreme structural skew in the data, with pitches recorded as Not Challenged more than 95% of the time. During the Naive Bayes modeling, this severe class imbalance forced the empirical model into the majority-class trap—automatically predicting that a pitch would never be challenged to artificially inflate global accuracy at the expense of a 0.00 recall rate.

To prevent the Decision Trees from falling into this same optimization trap, the pipeline bypasses unweighted training entirely. Instead, for the two challenge intent tasks, Scikit-Learn's built-in class_weight='balanced' hyperparameter is injected directly into the model initializations. When activated, the tree algorithm calculates an explicit weight multiplier that scales inversely with class frequencies:

$$\text{Weight} = \frac{\text{Total Training Samples}}{\text{Number of Unique Classes} \times \text{Samples in Class}}$$

This calculated multiplier is applied directly to the Gini and Entropy impurity metrics at every single node split during training. By heavily penalizing misclassifications on the rare Challenged pitches, the algorithm is forced to ignore the sheer background frequency of the data. This shifts the model's focus toward isolating the underlying physical tracking coordinates and high-leverage situational counts that actually drive a player's strategic decision to appeal.

Results

To evaluate the predictive performance of the Decision Tree framework, the pipeline was executed across the four predictive tasks. Three structurally distinct tree configurations were trained and tested for each task using stratified 80/20 data partitions to establish a granular performance profile:

  • Tree 1 (Shallow Gini): Optimized for high interpretability; restricted to a maximum depth of 3 layers using Gini Impurity.
  • Tree 2 (Deep Entropy): Optimized for capturing complex interactions; allowed to scale to a maximum depth of 5 layers using Entropy.
  • Tree 3 (Regularized Gini): Optimized to prevent overfitting; restricted to a depth of 4 layers and requiring a minimum of 20 samples per terminal leaf node using Gini Impurity.

Batter Challenge Intent

By proactively deploying the class_weight='balanced' parameter, all three tree configurations successfully bypassed the majority-class trap that heavily degraded the empirical Naive Bayes model. Instead of blindly predicting Not Challenged, the tree splits mapped out clear spatial and situational thresholds.

  • Tree 1 (Shallow Gini): Achieved an overall accuracy of 0.657, and the strongest recall (0.83) for the Challenged minority class, identifying 794 of the 953 Challenged pitches in testing.
  • Tree 2 (Deep Entropy): Achieved an overall accuracy of 0.751, with strong recalls for both the Challenged (0.82) and Not Challenged (0.75) classes.
  • Tree 3 (Regularized Gini): Achieved an overall accuracy of 0.797, strongest of the three trees generated for this task. It correctly identified the most Not Challenged pitches (16316), but struggled with identifying challenges compared to the other trees, with a Challenged recall of 0.71.


Batter Challenge Outcome

This task models whether an active batter challenge will result in an Overturned ball or a Confirmed strike. Because this data subset only tracks pitches where a challenge was actively executed, the classes are naturally balanced in the training pool.

  • Tree 1 (Shallow Gini): Achieved an overall accuracy of 0.615, strongest of the three trees generated for this task.
  • Tree 2 (Deep Entropy): Achieved an overall accuracy of 0.603. It correctly identified the most Confirmed challenges (349), but with a weak recall of 0.49 for Overturned challenges.
  • Tree 3 (Regularized Gini): Achieved an overall accuracy of 0.609. It produced the most balanced results of the three trees, with a recall of 0.60 for the Confirmed class and 0.62 for the Overturned class


Defense Challenge Intent

Predicting catcher and pitcher challenges represents the steepest data skew in these four tasks (97.56% Not Challenged rows). Proactive balancing forced the splitting nodes to focus on characteristics driving the minority class.

  • Tree 1 (Shallow Gini): Achieved an overall accuracy of 0.713, by far the lowest of these three trees. While it preformed well with the minority class (0.95 Challenged recall score), its 0.71 Not Challenged recall was the lowest of the three.
  • Tree 2 (Deep Entropy): Achieved an overall accuracy of 0.831. It correctly identified 1117 of the 1158 Challenged pitches, most of the three trees.
  • Tree 3 (Regularized Gini): Achieved an overall accuracy of 0.852, strongest of the three trees generated for this task, with strong recall scores for both the Challenged (0.94) and Not Challenged (0.85) classes.


Defense Challenge Outcome

The final task evaluates whether a catcher or pitcher's challenge will successfully overturn a called ball into a strike. The underlying data features a slight natural advantage toward success, tracking a baseline split of 42.2% Confirmed vs. 57.8% Overturned in training.

  • Tree 1 (Shallow Gini): Achieved an overall accuracy of 0.608. While it correctly predicted 571 of the 672 Overturned challenges, it struggled badly with Confirmed challenges (0.28 recall score).
  • Tree 2 (Deep Entropy): Achieved an overall accuracy of 0.616, strongest of the three trees generated for this task. Like the other two trees, it's heavily skewed towards predicting Overturned.
  • Tree 3 (Regularized Gini): Achieved an overall accuracy of 0.613, correctly predicting just one less Confirmed challenge and three less Overturned challenges than Tree 2.

Conclusions

The implementation of the non-parametric Decision Tree framework across the four core tasks offers a compelling structural contrast to the probabilistic baseline established in the Naive Bayes section. Most notably, a direct comparison of global validation metrics reveals that Decision Trees achieve a superior predictive edge when modeling player intent. For the batter challenge intent task, while the calibrated Naive Bayes model balanced class detection at a lower global accuracy of 53.32%, the Deep Entropy Decision Tree (Tree 2) pushed predictive precision significantly higher, establishing a strong overall accuracy of 75.10% while preserving a robust 0.82 recall for active challenges. An even more dramatic margin emerged within the heavily skewed defense challenge intent task. Here, the Regularized Gini Tree (Tree 3) advanced total testing accuracy to an elite 85.20%, tightly capturing the minority class with a 0.94 recall while maintaining a highly reliable 0.85 recall for unchallenged pitches. This noticeable jump in classification accuracy suggests that recursive, step-wise spatial partitioning is inherently better equipped to isolate player behavioral thresholds than an ensemble method constrained by a strict feature-independence assumption.

A cross-evaluation of the generated tree topologies uncovers the explicit feature hierarchies driving these structural improvements. Across all three architectural variations for both the batter and defensive intent tasks, the models consistently selected the continuous vertical and horizontal zone coordinates (plateTimeY_BotDiff, plateTimeY_topDiff, and plateTimeX)—as the primary root split checkpoints to maximize Information Gain. This uniform reliance on spatial margins proves that objective pitch locations, rather than baseline environmental metadata, function as the universal baseline driver behind a player’s split-second decision to execute an appeal. However, the deeper layers of the trees successfully exposed critical non-linear interaction rules that the Naive Bayes models completely ignored. For example, the intermediate branches isolated a significant inflation in challenge probability when high spatial deviations occurred simultaneously with a two-strike count (prePitchStrikes = 2) or a dwindling team resource pool (challengesLeft = 1). These multi-layer interaction checkpoints demonstrate why tree-based architectures scale so effectively in sports analytics pipelines; they natively reconstruct the conditional game-theory constraints and high-pressure context vectors that professional athletes evaluate under extreme temporal stress.

Conversely, evaluating the challenge outcome tasks reveals a near-identical performance ceiling between our two distinct modeling frameworks. Much like the Naive Bayes models, which stabilized at a validation ceiling of 61.59% for batters and 60.57% for defenders, the top-performing Decision Trees reached a matching plateau, maxing out at a 61.5% accuracy score for batters and a 61.6% accuracy score for defensive players. This mathematical convergence across different models confirms a fixed operational boundary in our current modeling space. While situational metadata features carry a proven, statistically significant signal that easily improves upon a random guess, they lack the intrinsic resolution to achieve high-confidence outcome precision on their own.
